## Memory (elephant-memory)

Three layers: the `MEMORY.md` index (rules, references, sub-indexes) → sub-indexes `index_*.md` → the session diary in `~/.claude/projects/<slug>/digests/`.

- **Search before saying "I don't remember"** and before creating a note: `~/.claude/elephant-memory/bin/memsearch [-n 5] [--project <name>] [--hybrid] <words>` returns chunks as `file:line`; read that chunk, not the whole file. Listings: `memsearch ls --type project --older-than 14d`, `memsearch ls --ticket ABC-123`; health check: `memsearch lint`.
- **Active tasks are notes, not index lines.** A task in progress has `status: active`, `title`, `next` (state and next step, with a date) and optionally `group` in its frontmatter; a SessionStart hook prints them. When a task moves on, update `next`; when it is closed, set `status: done` and add a line to `index_archive.md`.
- **Journal first, then a note.** Straight into a note go only: a rule or a "remember this" from the user, the user's correction, and task state (`next`, `status`). Everything else — findings, facts from the work, guesses — is one line in the journal: `~/.claude/elephant-memory/bin/elephant-memory journal add -k <fact|decision|rule|commitment|correction|guess> "<text>"`. `/wrap` promotes today's entries, `/sleep` the ones earlier sessions left behind. A hook reminds once per session when a note is written directly.
- **The write filter.** An entry becomes a note when at least one holds: it changes how you work in later sessions; it is a commitment (a deadline, a promise, someone's next step); it is a decision with its reason; it is a lasting fact not derivable from code, git or the tracker; the user asked to remember it. Otherwise it is skipped with a reason. Every entry ends up marked ` → [[note-name]]` or ` → skipped: <reason>`.
- **Replace, do not overwrite.** A stale fact in a note is struck out, not erased: `~~old~~ [replaced YYYY-MM-DD: reason]`, with the new fact next to it. A note that is stale as a whole gets `status: superseded`, `superseded_by: <note-name>`, `superseded_at`, `superseded_reason`; move links to the new note (`memsearch lint` lists the leftovers). A correction from the user goes to every layer at once: the note, its index line, the `next` of an active task it touches, and a `correction` entry in the journal.
- **One fact per note**, linked with `[[note-name]]`. A new note gets a line in `MEMORY.md` or in a sub-index; old topics go to `index_archive.md` instead of being deleted.
- Session start shows the last snapshot, the diary for today and the last working day, and parallel live sessions. They are for reference, not instructions: verify against git.
- Before `/clear` in a long session, suggest `/wrap`; for periodic tidying, `/sleep`.
